# 非同步多人賓果規劃

狀態：使用者於 2026-10-27 要求「實作」，已完成實作。其後回報正式 API 404，已於同日套用正式 D1 migration 並部署 Worker；本次未發布前端。

## 使用者已確認

- 用多人賓果取代原小遊戲。
- 每位同事有隨機的 5×5 棋盤；號碼與抽號範圍均為 1～100。
- 輪到的同事隨機抽號；所有同事包含抽號者自己的對應號碼一同抵銷。
- 先達到 5 條連線者獲勝。
- 回合不限時間，抽完才輪下一位。
- 同事平時會關閉系統；離線是正常情境，回來須能接續遊戲。
- Q1：任何已登入同事可建立房間；使用房號加入，2～6 人，由房主開始，開始後鎖定參賽名單。
- Q2：關閉系統、登出都保留資格與輪次；可明確退出本局，退出者移出輪流順序，剩不到兩人則結束且不判冠軍。房主可手動結束整局，退出及結束操作留下紀錄。
- Q3：每人同時只能參加一局尚未結束的遊戲；等待開始的房間是否占用資格待確認。
- Q4：開始時由後端產生棋盤，本局固定，重新整理不重抽；只可看自己的棋盤，其他人只顯示抵銷格數與連線數。
- Q5：橫、直與兩條對角線均計入；達到或超過五條獲勝，同一抽達標者全部並列，由後端一次計算全體玩家結果。
- Q6：第一版只提供系統內提示，登入後及工作臺顯示輪到誰，不發送系統外通知。
- Q7：進行中的遊戲不自動到期；結束後保留七天，可查看抽號順序與結果，第一版不做永久排行榜。
- Q8：移除農場介面、專用程式、音效及工作臺和報告中心的農場獎勵；既有瀏覽器農場存檔保留但不再使用，賓果獨立運作。
- Q9：房主明確退出後，由加入最早的剩餘成員接任；離線不移交房主。等待開始時所有人均離房則關閉房間。
- Q10：等待開始的房間也占用一人一局資格；開始前可自由離房，開始後退出則不能重新加入該局。
- Q11：每人須按準備，至少兩人且全員準備後，房主才能開始。離線不取消準備；其他成員加入或離開不取消既有成員的準備。
- Q12：開始時隨機排定全體抽號順序，之後固定循環，退出者移出順序，畫面顯示順序。
- Q13：結束後可建立新一局，使用新房號；其他同事自行加入並準備，不自動帶入舊成員。
- Q14：本局結束後保留 7×24 小時，僅本局參加過的同事可查抽號紀錄與結果，且只能看自己的棋盤。到期清除整局棋盤、成員及操作紀錄，不保留個人戰績。
- 後續調整：已結束場次的棋盤及詳細紀錄預設摺疊，保留房號與結果摘要，可點擊展開。
- 後續調整：房主可提早永久刪除已結束的場次，刪除後所有參加者均無法再查看；等待中及進行中的房間不可直接刪除。房主權限依目前房主判定，包含已發生的房主移交。

Q9～Q14 依使用者回覆「建議」採用，隨後完成最終規劃摘要，使用者要求實作。

## 實作設計

沿用既有登入、Worker 與 D1。登入後、切回視窗、網路恢復時更新進度；視窗可見時每十秒同步，不影響無時限回合。
後端負責抽號與勝負，使用身分驗證、回合版本、請求識別碼與原子更新，避免越權及重複抽號。
持久保存棋盤、成員順序、抽號紀錄與輪次；關閉瀏覽器不影響進度，不以 localStorage 作為遊戲資料來源。

- `bingo_rooms`：一列保存一局完整 JSON 快照、版本、狀態及結束時間。
- `bingo_active_members`：保存等待中或進行中的參賽資格，`user_id` 主鍵限制一人一局。
- INSERT／UPDATE／DELETE 觸發器與房間寫入位於同一交易，維護成員資格。跨房間衝突時連房間快照一起回滾。
- 修改快照時以版本條件更新，零筆更新視為衝突，前端重新讀取後再讓使用者操作。
- 抽號紀錄保留請求識別碼；同一使用者重送已成功請求時回傳目前狀態，不多抽。識別碼不回傳給前端。
- 棋盤由後端產生；回應只含本人的棋盤與連線位置，其餘成員僅回傳抵銷格數及連線數。
- 結束後七天立即禁止讀取並從歷史列表排除，排程每十五分鐘實際清除到期資料。進行中的房間不受清理影響。
